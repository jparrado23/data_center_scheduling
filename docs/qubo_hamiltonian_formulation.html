Quantum Scheduling Formulation

Full MILP Scope and Reduced QUBO Hamiltonian

This note separates the complete energy-aware data-center scheduling model solved with Gurobi from the reduced QUBO Hamiltonian intended for quantum, quantum-inspired, and hybrid experiments.

1. Problem Definition

We schedule flexible GPU workloads in a data center with heterogeneous GPU clusters. Each job has a feasible start window, duration, GPU demand, CPU demand, memory demand, and an implied IT power coefficient. Power is not treated as a separate cluster capacity; it is a consequence of the selected workloads. The scheduler chooses a cluster and start time for each job while minimizing facility energy cost and respecting resource and energy-system constraints.

Goal. The full model is the operational source of truth and is solved classically with Gurobi. The QUBO is a reduced binary formulation used to test quantum feasibility on smaller or decomposed scheduling subproblems.

2. Full Mathematical Formulation

The full formulation keeps the operational energy variables continuous. With constant or exogenous PUE it is a MILP. With utilization-dependent PUE it may become quadratic unless the PUE effect is approximated or linearized.

Objective With Renewable, Grid, and Peak Cost

Full cost objective \[ \min \sum_{t\in\mathcal{T}} \left( c^R R_t\Delta t + c^G_t Q_t\Delta t \right) + \pi^{peak}P^{excess} \]

The objective pays for renewable energy, grid energy, and facility-power peak excess. The scheduling variables influence the objective through facility load, which is linked to IT load and PUE below.

Activity and Load Definitions

Activity coefficient \[ a_{i,s,t} = \begin{cases} 1, & s \le t < s+d_i,\\ 0, & \text{otherwise.} \end{cases} \]
Cluster and total IT load \[ L^{IT}_{k,t}(x)= \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} p_i a_{i,s,t}x_{i,k,s} \] \[ L^{IT}_{t}(x)=\sum_{k\in\mathcal{K}}L^{IT}_{k,t}(x) \]

Assignment Constraint

Every job must be scheduled exactly once. This means the model cannot skip a job, and it also cannot assign the same job to two clusters or two start times.

\[ \sum_{k\in\mathcal{K}_i}\sum_{s\in\mathcal{S}_i} x_{i,k,s}=1 \qquad \forall i\in\mathcal{I} \]

GPU, CPU, and Memory Constraints

These constraints enforce the physical cluster capacities at every time slot. A job consumes resources in every slot in which it is active, so a job starting at \(s\) contributes to slot \(t\) only when \(a_{i,s,t}=1\). Power is not a separate cluster capacity here; it is derived from the scheduled jobs and used later in the energy balance and objective.

GPU capacity \[ \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} g_i a_{i,s,t}x_{i,k,s} \le G_k \qquad \forall k\in\mathcal{K},\forall t\in\mathcal{T} \]
CPU and memory capacity \[ \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} cpu_i a_{i,s,t}x_{i,k,s} \le CPU_k \qquad \forall k,t \] \[ \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} mem_i a_{i,s,t}x_{i,k,s} \le MEM_k \qquad \forall k,t \]

PUE Modeling

PUE converts IT power into facility power. IT load is the power consumed by the computing equipment. Facility power includes the extra cooling and electrical overhead required to operate that equipment. In the baseline, PUE is constant or exogenous by time slot:

\[ P^{fac}_t = PUE_t \cdot L^{IT}_t(x) \]

For an advanced model, PUE can depend on normalized IT utilization:

Affine utilization-dependent PUE \[ u_t=\frac{L^{IT}_t(x)}{L^{IT}_{max}}, \qquad PUE_t(u_t)=PUE_{low}-\beta u_t \] \[ P^{fac}_t(x)= PUE_{low}L^{IT}_t(x) - \frac{\beta}{L^{IT}_{max}}\left(L^{IT}_t(x)\right)^2 \]
Interpretation. Load-dependent PUE is an objective transformation, not a hard feasibility constraint. It rewards higher utilization if PUE decreases with load, so it must be balanced against resource limits and peak penalties.

Energy Balance and Renewable Limit

The energy balance forces supply to equal demand in each slot. Facility demand plus battery charging must be covered by renewable consumption, grid import, and battery discharge. Renewable consumption cannot exceed available renewable generation.

\[ R_t + Q_t + B^d_t = P^{fac}_t(x) + B^c_t \qquad \forall t\in\mathcal{T} \] \[ 0\le R_t\le r_t,\qquad Q_t\ge 0 \qquad \forall t \]

Facility Peak

The peak variable records the maximum facility power observed across the horizon. The excess variable charges only the amount above the contracted power threshold.

\[ P^{peak}\ge P^{fac}_t(x) \qquad \forall t\in\mathcal{T} \] \[ P^{excess}\ge P^{peak}-\bar{P}^{contract}, \qquad P^{excess}\ge 0 \]

Battery Modeling

Battery variables allow the model to move energy across time. Charging increases state of charge after charge efficiency losses; discharging decreases state of charge after discharge efficiency losses. If battery use is disabled, these variables and constraints are removed or fixed to zero.

Charge, discharge, and state of charge \[ 0\le B^c_t\le \bar{B}^{power}, \qquad 0\le B^d_t\le \bar{B}^{power} \] \[ 0\le SOC_t\le \bar{B}^{energy} \] \[ SOC_t = SOC_{t-1} + \eta^c B^c_t\Delta t - \frac{B^d_t}{\eta^d}\Delta t \qquad \forall t \]
Battery interpretation. This general model allows grid price arbitrage unless an additional renewable-only charging constraint is introduced.

3. Reduced QUBO Problem Description

The QUBO formulation is deliberately reduced. It keeps only binary scheduling decisions and binary slack variables needed for selected constraints. Continuous grid, renewable, exact facility-peak, and battery variables are not included in the first QUBO.

QUBO Variables

VariableDomainMeaning
\(x_{i,k,s}\)\(\{0,1\}\)Job \(i\) starts on cluster \(k\) at feasible start slot \(s\).
\(y_{k,t,b}\)\(\{0,1\}\)Binary bit used to encode unused GPU slack at cluster \(k\), time \(t\).

Reduced Parameters

SymbolMeaning
\(g_i\)GPU demand of job \(i\).
\(G_k\)GPU capacity of cluster \(k\).
\(p_i\)IT power of job \(i\), assumed cluster-independent in the reduced QUBO.
\(c_t\)Effective energy price used by QUBO. It may be grid-only or a simplified renewable-aware price.
\(a_{i,s,t}\)Precomputed activity coefficient.
\(\lambda_A,\lambda_G,\lambda_P\)Assignment, GPU, and peak/load penalty weights.
Reduction boundary. The first QUBO is not an exact reformulation of the full MILP. It does not explicitly decide renewable versus grid supply. Instead, it uses an effective time price and a load shaping term to represent the energy timing and peak-pressure signal.

4. QUBO Mathematical Formulation

4.1 Assignment Penalty

Define the feasible assignment set for each job. Each element \((k,s)\) is one complete scheduling option: run job \(i\) on cluster \(k\) starting at slot \(s\).

\[ \mathcal{A}_i= \{(k,s): k\in\mathcal{K}_i,\ s\in\mathcal{S}_i\} \]

The one-job assignment constraint is:

\[ \sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s}=1 \]

In QUBO we do not impose this equality as a hard linear constraint. Instead, we add a penalty that is minimized when the equality is satisfied:

\[ H_{assign} = \lambda_A \sum_{i\in\mathcal{I}} \left( \sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s} - 1 \right)^2 \]

Let \(S_i=\sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s}\). Then:

\[ (S_i-1)^2=S_i^2-2S_i+1 \] \[ S_i^2= \sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s} + \sum_{\substack{(k,s),(k',s')\in\mathcal{A}_i\\(k,s)\ne(k',s')}} x_{i,k,s}x_{i,k',s'} \]

The second sum uses ordered unequal pairs, so no coefficient 2 is written. Ignoring the constant, the expanded assignment Hamiltonian is:

\[ \boxed{ H_{assign} = \lambda_A \sum_{i\in\mathcal{I}} \left[ \sum_{\substack{(k,s),(k',s')\in\mathcal{A}_i\\(k,s)\ne(k',s')}} x_{i,k,s}x_{i,k',s'} - \sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s} \right] } \]
The positive quadratic terms penalize choosing two scheduling options for the same job. The negative linear term rewards choosing at least one option. Together, the minimum is reached when exactly one option is selected.

4.2 GPU Constraint Hamiltonian

To avoid confusing GPU usage with IT power load, define GPU demand in cluster \(k\), time \(t\), as \(D^G_{k,t}(x)\):

\[ D^G_{k,t}(x)= \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} g_i a_{i,s,t}x_{i,k,s} \]

This counts all GPUs requested by jobs active in that cluster and slot. The physical GPU capacity constraint is:

\[ D^G_{k,t}(x)\le G_k \qquad \forall k,t \]

QUBO handles equalities more naturally than inequalities. We therefore introduce unused-GPU slack \(u_{k,t}\), which represents the number of GPUs left idle in cluster \(k\) at time \(t\):

\[ D^G_{k,t}(x)+u_{k,t}=G_k \]

Encode slack with binary variables:

\[ u_{k,t}= \sum_{b=0}^{B_k-1}2^b y_{k,t,b}, \qquad B_k=\left\lceil\log_2(G_k+1)\right\rceil \]

The GPU Hamiltonian penalizes any assignment and slack combination that does not exactly explain the available GPU capacity:

\[ \boxed{ H_{GPU} = \lambda_G \sum_{k\in\mathcal{K}}\sum_{t\in\mathcal{T}} \left( \sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} g_i a_{i,s,t}x_{i,k,s} + \sum_{b=0}^{B_k-1}2^b y_{k,t,b} - G_k \right)^2 } \]

4.3 Energy Cost Hamiltonian

The reduced QUBO does not choose explicit renewable and grid flows. Instead, it uses an effective time-dependent price \(c_t\). This price can represent grid price, a renewable-aware adjusted price, or any scenario-specific signal we want the quantum model to follow.

\[ \boxed{ H_{energy} = \sum_{t\in\mathcal{T}} \sum_{k\in\mathcal{K}} \sum_{i\in\mathcal{I}} \sum_{s\in\mathcal{S}_i} c_t\Delta t\ p_i a_{i,s,t}x_{i,k,s} } \]

Equivalently, each assignment variable receives a linear coefficient \(E_{i,k,s}\). This coefficient is the total energy cost of choosing option \((i,k,s)\), computed by summing the active slots of the job:

\[ E_{i,k,s}= \sum_{t\in\mathcal{T}} c_t\Delta t\ p_i a_{i,s,t} \] \[ H_{energy}= \sum_{i,k,s}E_{i,k,s}x_{i,k,s} \]

4.4 Peak Penalty Hamiltonian

Exact contracted facility-peak billing requires additional binary variables for peak level and excess. As a first QUBO-compatible proxy, use squared IT load. PUE is introduced in the next section, after the base peak proxy is defined.

\[ L^{IT}_t(x)= \sum_{k\in\mathcal{K}}\sum_{i\in\mathcal{I}}\sum_{s\in\mathcal{S}_i} p_i a_{i,s,t}x_{i,k,s} \] \[ \boxed{ H_{peak} = \lambda_P \sum_{t\in\mathcal{T}} \left(L^{IT}_t(x)\right)^2 } \]
This proxy discourages concentrating IT power in a single slot. It is not the same as squaring the total energy cost, and it is not exact contracted peak billing. Its role is to create a penalty against schedules with sharp load spikes.

4.5 PUE Integration

PUE is not added as a separate feasibility constraint. It converts IT load into facility load. In the QUBO, that means PUE modifies the energy cost term and, if desired, the peak/load-shaping term. With constant or exogenous PUE, this is just a time-dependent multiplier on IT load:

\[ H_{energy}^{PUE-fixed} = \sum_t c_t\Delta t\ PUE_t L^{IT}_t(x) \] \[ H_{peak}^{PUE-fixed} = \lambda_P \sum_t \left(PUE_t L^{IT}_t(x)\right)^2 \]

In this fixed-PUE case, both terms remain valid QUBO terms: \(H_{energy}^{PUE-fixed}\) is linear in the binary assignment variables, and \(H_{peak}^{PUE-fixed}\) is quadratic.

With affine utilization-dependent PUE, PUE itself depends on the selected schedule because utilization depends on \(L^{IT}_t(x)\). This turns facility energy into a quadratic expression in the same binary assignment variables, without introducing additional QUBO variables:

\[ PUE_t(x)= PUE_{low} - \frac{\beta}{L^{IT}_{max}}L^{IT}_t(x) \] \[ P^{fac}_t(x)= PUE_{low}L^{IT}_t(x) - \frac{\beta}{L^{IT}_{max}}\left(L^{IT}_t(x)\right)^2 \]

Therefore the PUE-aware facility-energy Hamiltonian is:

\[ \boxed{ H_{facility} = \sum_{t\in\mathcal{T}} c_t\Delta t \left[ PUE_{low}L^{IT}_t(x) - \frac{\beta}{L^{IT}_{max}} \left(L^{IT}_t(x)\right)^2 \right] } \]

This term replaces the simple energy Hamiltonian when the utilization- dependent PUE model is active. The linear part charges each selected assignment for facility energy. The quadratic part captures the PUE efficiency gain from simultaneous load. Because that quadratic coefficient is negative, it can encourage consolidation; the base peak proxy and GPU constraints are therefore essential counterbalances:

\[ H_{facility}+H_{peak} = \sum_t \left[ c_t\Delta t PUE_{low}L^{IT}_t(x) + \left( \lambda_P - c_t\Delta t\frac{\beta}{L^{IT}_{max}} \right) \left(L^{IT}_t(x)\right)^2 \right] \]
Practical warning. If fixed PUE is used, adding PUE to the peak penalty remains quadratic. If affine utilization-dependent PUE is inserted inside the squared peak penalty, \(\sum_t(P^{fac}_t(x))^2\), the term becomes quartic because \(P^{fac}_t(x)\) already contains \((L^{IT}_t(x))^2\). To keep a true QUBO, we should either use fixed PUE for the peak proxy, keep the peak proxy on IT load, or approximate the utilization-dependent peak effect.

4.6 Final Hamiltonian

The compact reduced QUBO Hamiltonian with fixed PUE applied to both energy and peak is:

\[ \boxed{ H_{total} = H_{energy}^{PUE-fixed} + H_{assign} + H_{GPU} + H_{peak}^{PUE-fixed} } \]

If utilization-dependent PUE is used for energy cost, replace \(H_{energy}^{PUE-fixed}\) by \(H_{facility}\). In that case, be careful with the peak term: use \(H_{peak}\) on IT load or an approximation if we need to remain inside QUBO.

Developed Form

\[ \begin{aligned} H_{total} = & \sum_{t} c_t\Delta t\ PUE_t L^{IT}_t(x)\\ & + \lambda_A \sum_i \left[ \sum_{\substack{(k,s),(k',s')\in\mathcal{A}_i\\(k,s)\ne(k',s')}} x_{i,k,s}x_{i,k',s'} - \sum_{(k,s)\in\mathcal{A}_i}x_{i,k,s} \right]\\ & + \lambda_G \sum_{k,t} \left( \sum_{i,s} g_i a_{i,s,t}x_{i,k,s} + \sum_{b=0}^{B_k-1}2^b y_{k,t,b} - G_k \right)^2\\ & + \lambda_P \sum_t \left(PUE_t L^{IT}_t(x)\right)^2. \end{aligned} \]
Implementation interpretation. D-Wave, QAOA, or a classical QUBO solver receives only expanded linear and quadratic coefficients. The activity terms \(a_{i,s,t}\), prices, powers, and GPU demands are preprocessing coefficients used to build the Hamiltonian.
